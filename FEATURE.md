# Parallel — Feature Specification

> **Purpose:** A practical feature checklist for implementing Parallel.
>
> **Source:** `PARALLEL — Source of Truth` + `PARALLEL — Master Blueprint`
>
> This document defines the features that belong in the product. It does not define implementation details; those belong in the database, API, UI, and code.

---

## 1. Product Core

Parallel is a social identity discovery platform for exploring different versions of yourself.

The core loop is:

**Explore → discover a self → enter that self → meet people/content → experiment → act → learn → evolve → discover another self.**

The product is not primarily a generic social network, personality test, or AI chatbot.

---

# 2. MVP Features

These are the features required to prove the core identity-discovery thesis.

## 2.1 Authentication

### Purpose

Allow users to create and access their Parallel account.

### MVP

- Sign up
- Login
- Logout
- Protected authenticated areas
- User account

### Later

- More advanced authentication options

---

## 2.2 Onboarding

### Purpose

Collect first-party interest signals before the user has a social graph.

### MVP

- Present fun preference questions
- Collect answers
- Persist answers
- Use answers as initial interest signals
- Complete onboarding before showing the main identity experience

### Example questions

- Friday night preference
- Learn vs make
- Plan vs improvise
- Naturally chosen activities

---

## 2.3 Parallel Map

### Purpose

Give the user the first major "aha" moment by showing different versions of themselves.

### MVP

- Display user's Parallels
- Display relative interest strength
- Use playful identity labels
- Show percentages/strength indicators
- Make clear these are interest indicators, not psychological diagnoses

### Example

```text
Builder       42%
Music Head    26%
Gamer         18%
Explorer      14%
```

### Later

- Momentum arrows
- More advanced visualization
- Rich evolution visualization

---

## 2.4 Enter a Parallel

### Purpose

Let users explore a different discovery context based on one of their identities.

### MVP

- Select a Parallel
- Enter that Parallel's context
- Change the content/discovery experience
- Show people, content, communities or challenges relevant to that Parallel

### Core rule

A Parallel is **not a separate account**.

It is a different discovery context for the same person.

---

## 2.5 Parallel-Specific Discovery / Feed

### Purpose

Provide useful discovery inside a selected Parallel.

### MVP

- Content associated with a Parallel
- Basic feed/discovery experience
- Content filtered by the active Parallel
- Initially use curated/seeded content if necessary

### Examples

**Builder**

- Projects
- Programming discoveries
- Hackathons

**Music Head**

- Artists
- Performances
- Music-related discovery

---

## 2.6 Basic Interactions

### Purpose

Allow user behavior to create additional interest signals.

### MVP

Support meaningful interactions such as:

- View
- Like
- Save
- Search
- Follow
- Challenge completion

These interactions become behavioral signals for future personalization.

---

## 2.7 People Discovery

### Purpose

Help users meet people through identity and interest overlap.

### MVP

- Discover people through unusual interest combinations
- Show relevant overlap
- Avoid presenting the system as a scientific personality measurement

### Core principle

Recommend people through identity/interests rather than only traditional "People You May Know" logic.

---

## 2.8 Identity Evolution

### Purpose

Show how the user's interests change over time.

### MVP

- Store historical identity snapshots
- Show change in Parallel strengths
- Highlight meaningful evolution

### Possible highlights

- Newest Parallel
- Biggest evolution
- Most explored identity
- Most unexpected interest

### Later

- Full "Parallel Wrapped" experience

---

# 3. Identity Engine Features

These are central to Parallel's long-term differentiation.

## 3.1 Interest Signals

Track signals generated by:

- Onboarding answers
- Selected interests
- Content views
- Likes
- Saves
- Searches
- Follows
- Community participation
- Challenge completion
- Other voluntary interactions

### Rule

Start simple with rules-based ranking and progressively add behavioral weighting, collaborative filtering and embeddings.

---

## 3.2 Parallel Strength

Calculate a user's current strength for each Parallel.

The result should evolve as the user's behavior changes.

The system should avoid presenting the result as:

- A psychological diagnosis
- A personality test
- A scientific measurement

It should be presented as a playful identity map.

---

## 3.3 New Parallel Discovery

### Purpose

Detect emerging interest combinations.

### Example

Repeated interaction with:

- Photography
- Architecture
- Street art
- Travel

could produce:

**The Urbanist**

### User controls

The user should be able to:

- Explore the suggestion
- Understand why it was suggested
- Reject it
- Edit/remove it
- Hide it

---

## 3.4 What If?

### Purpose

Allow users to experiment with hypothetical versions of themselves.

Example:

> "What if I became a photographer?"

The system creates a temporary discovery world around that possibility.

### Core rule

This is identity experimentation, not a claim about the user's true personality.

---

## 3.5 Ghost Mode

### Purpose

Let users privately explore a new or hypothetical Parallel.

### Behavior

- New "What If?" exploration starts privately
- Not visible to friends
- Not reflected on the public map
- No notifications about the exploration
- User explicitly chooses when to make it public

---

## 3.6 Hidden Parallels

### Purpose

Reward curiosity and exploration.

### Behavior

- Emerging identities can remain hidden
- User may need to explore topics or complete challenges
- Completing activities can unlock hints/discovery

---

## 3.7 Identity Collisions

### Purpose

Find unexpected intersections between interests.

### Examples

- Builder + Music → Creative Engineer
- Gamer + Foodie → Gaming Foodie
- Photographer + Night Owl → Night Photographer

These intersections can drive:

- Recommendations
- People discovery
- Communities
- Challenges

---

# 4. Quests & Identity Experiments

## 4.1 Identity Experiments

Small activities associated with a Parallel.

### Examples

**Builder**

- Build something in two hours

**Music Head**

- Discover an unknown artist

**Photographer**

- Capture something unusual

**Explorer**

- Visit somewhere new

Completing activities creates additional signals.

---

## 4.2 Quests

Chains of 3–5 Identity Experiments.

### MVP direction

- Quest
- Multiple steps
- Progress tracking
- Completion
- Reward

### Rewards can include

- Badge
- Cosmetic profile frame
- Hidden Parallel hint

### Later

- Streaks
- Seasonal quests
- AI-generated quests

---

## 4.3 Parallel Streaks

Track active engagement with a Parallel through:

- Challenges
- Content
- Real-world check-ins

### Later

- Streak decay
- Warning notifications
- Streak-based retention mechanics

---

# 5. Social Features

## 5.1 Follows

- Follow users
- Unfollow users
- Store relationship

---

## 5.2 Parallel Twin

### Purpose

Find someone whose current interest combination is unusually similar.

### MVP direction

- Compute similarity
- Show shared interests/Parallels
- Present the match as discovery, not scientific personality similarity

---

## 5.3 Communities

### Purpose

Allow communities to emerge from shared behavior/intersections.

### Direction

- Detect common interest intersections
- Surface emerging communities
- Support community membership
- Seed communities manually during early cohorts

Communities should emerge from behavior rather than simply becoming empty user-created groups.

---

## 5.4 Collab Parallels

### Purpose

Let two friends temporarily combine their Parallels.

### Example

```text
User A: Explorer
        +
User B: Foodie
        ↓
Joint discovery world
```

### Behavior

- Select one Parallel per person
- Create temporary shared context
- Shared challenge
- Shared Identity Card

This is designed for pairs/duos.

---

## 5.5 Parallel Roulette

### Purpose

Create low-stakes identity-based stranger discovery.

### Behavior

- User opts in
- Selects a Parallel
- Gets matched with someone with an unusual shared intersection
- Time-boxed interaction
- Approximately 10–15 minutes

### Safety requirements

- Reporting
- Blocking
- Moderation
- Safety timeout

---

# 6. Real-World Discovery

### Purpose

Move Parallel from digital discovery to real-world activity.

### Examples

**Music Parallel**
→ Indie gig

**Photography Parallel**
→ Photo walk

**Explorer Parallel**
→ Nearby activity

### Core loop

**Discover → try → experience → evolve**

### MVP direction

Link to existing events/places rather than building ticketing or booking.

---

# 7. Identity Cards

### Purpose

Create shareable artifacts from meaningful Parallel experiences.

### Generate cards for

- New Parallel discovered
- Quest completed
- Parallel Twin
- Parallel Wrapped

### Design requirements

- Portrait-oriented
- Minimal text
- Personal/ego-focused
- On-brand
- Shareable
- No unnecessary app UI chrome

Identity Cards are a major part of the organic growth loop.

---

# 8. Parallel Wrapped

### Purpose

Create a recurring recap of the user's identity evolution.

### Recap can include

- Biggest evolution
- Most explored identity
- Weirdest new intersection
- Most active streak
- Parallel Twin
- Other meaningful changes

### Output

Swipeable, story-style cards designed to be shared.

### Timing

- Monthly
- Annual

---

# 9. Notifications

### Purpose

Keep users informed about meaningful activity.

Potential notifications:

- Streak warning
- Quest completion
- New Parallel discovered
- Parallel Twin match
- Social activity
- Other meaningful system events

### Later

Real-time delivery through Socket.IO and Redis.

---

# 10. Feed & Content

Content exists to support the active Parallel rather than becoming the product itself.

### Content can include

- Posts
- Articles
- Events
- Challenge prompts
- Other Parallel-relevant discovery

The active Parallel determines the information environment.

---

# 11. Profile & Identity Controls

### Profile

- Basic user profile
- Identity map
- Parallel visibility
- Shared identity information

### Controls

Users should be able to:

- Reject/remove Parallels
- Hide interests
- Control visibility
- Manage personalization
- Delete behavioral history where supported

---

# 12. Privacy & Trust

These are required product capabilities as the identity system becomes more personalized.

### Required

- Explain why a Parallel was suggested
- Reject/remove/hide Parallels
- Hide individual interests
- Visibility controls
- Ghost Mode
- Data export
- Account/data deletion

### Product language

Never use:

- Psychological diagnosis
- Clinical claims
- Personality-test framing
- Opaque "personality scores"

Personalization should remain explainable.

---

# 13. AI Features

AI stays behind the experience.

### AI can support

- Semantic interest classification
- Content understanding
- Identity descriptions
- Emerging identity detection
- Quest generation
- Wrapped narrative generation
- Recommendation assistance

### AI should NOT become

- A chatbot-first product
- A visible "Parallel AI" character
- The primary user experience

### Processing

AI-heavy operations should run asynchronously/background rather than blocking normal user requests.

---

# 14. Real-Time Features

Post-MVP / later-stage features:

- Presence
- Live notifications
- Matching updates
- Real-time collaboration
- Ambient Rooms

### Ambient Rooms

Live audio rooms scoped to a Parallel.

**Explicitly post-MVP.**

---

# 15. Growth Features

The main growth loop is:

**User → identity result → share → friend becomes curious → friend joins → identity result → social overlap → more content → better recommendations → more sharing**

Important growth mechanics:

- Identity Cards
- Parallel Twin
- Comparisons
- Hidden Parallels
- Quests
- Wrapped
- Collab Parallels

Sharing should feel like a consequence of using the product, not a forced invite mechanic.

---

# 16. MVP Boundary

## Build for MVP

1. Authentication
2. Onboarding
3. Interest signals
4. Identity generation
5. Parallel Map
6. Enter a Parallel
7. Parallel-specific discovery/feed
8. Basic interactions
9. Basic profile
10. People discovery
11. Basic identity evolution

## Defer

- Advanced machine learning
- Complex messaging
- Video calls
- Microservices
- Kubernetes
- Ambient Rooms
- Full-scale real-time infrastructure
- Marketplace/ticketing
- Advanced recommendation systems

The MVP exists to prove:

> A new user signs up → answers questions → receives an identity map → enters a Parallel → sees a meaningfully different discovery world → discovers a surprising new Parallel.

## Source-of-Truth Rule

Every feature should strengthen at least one of these:

1. Identity discovery
2. Identity exploration
3. Identity-based social connection
4. Real-world experimentation
5. Learning/evolution

If a feature does not strengthen these, it is secondary and should not take priority over the core loop.
